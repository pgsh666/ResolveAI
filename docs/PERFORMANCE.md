# 性能、成本与统计口径

文档同步：2026-10-16。当前实现见 model_usage、workflow_runs 和性能聚合服务，已验证范围见[指标汇总](RESULTS.md)。个人试用台账与原始运行记录不随公开副本发布。

## 指标来源与权限

`GET /api/v1/performance/metrics`仅管理员可读取。前端自动带登录 Cookie；裸请求会返回401，非管理员返回403。模型/工单台账按可见工单范围汇总，HTTP/缓存指标是运行服务的观测数据，不是每个客户的业务收益。

| 指标 | 来源/口径 |
| --- | --- |
| HTTP P50/P95 | Redis或进程内有界样本，默认最近1000次请求；按路由区分 |
| 机器工作流 P50/P95 | workflow_runs：同步开始/入队至后台该段结束，含排队、失败与审批恢复，不含人工等待 |
| 客户确认解决周期 | 工单创建至客户主动确认；只统计明确解决样本，含人工和客户等待 |
| 模型尝试与Token | model_usage逐次记录，包含重试、改写、重生成及有用量的解析失败 |
| 旧版模型摘要 | 仅保留诊断数量，不再计入调用数、Token、模型分组或成本平均值；不删除原记录 |
| 缓存与保护 | 命中/未命中、限流/并发拒绝计数与当前配置 |

机器“工作流段”的P95、单次模型API的P95与客户解决周期不是同一项时长；多轮和人工审批可能对应多段工作流。后台重启不能清空数据库台账，Redis观测窗口也不能替代长期台账。

## 费用不能把未知记成零

- 显式输入/输出单价均大于0时，使用该阶段配置费率估算，注明输入按未缓存费率处理。
- 未显式配置时，已识别DeepSeek模型使用2026-10-12的版本化官方价格快照，按缓存命中/未命中及峰谷给出上下界；快照有效至2026-11-11，之后未更新则为未知。
- 未识别模型、缺用量、无可用费率或旧摘要不能证明完整记录时，`estimated_cost_usd=null`，不能补零或伪造历史费用。
- `known_estimated_cost_usd`为完整费用台账的合计，`complete_cost_calls`为分母，`recorded_average_cost_per_call_usd`为二者之比。前端“平均估算成本（非账单）”只采用这组完整记录，标注样本数和合计，不显示旧摘要或把未知费用补零。样本数从本机台账动态统计，不硬编码开发者试用数据；公开副本初始无调用记录。
- API 的全台账 `estimated_cost_usd` / `average_cost_per_call_usd` 仍保留严格口径：若新台账本身缺少费用，完整合计/平均值仍为未知；`unknown_cost_calls`仅统计逐次台账中未知项。它不影响前端已经明确限定口径的“完整记录平均值”。零费用记录和已知扣费的失败尝试照常纳入，不能只选成功或非零调用。
- 旧 `assessment.model_trace` 摘要只计入诊断字段 `legacy_trace_calls`，不再影响任何台账平均值；历史对话、审计和原摘要不删除。无完整费用样本时前端显示“暂无完整费用记录”，不伪造 0 美元平均值。
- Demo没有模型API费用；其Token为近似估值，与真实提供商用量分开记录。
- 每次尝试都有唯一事件编号，可与workflow_run_id关联；账本不会因最终assessment覆盖而漏掉早先调用。

这是模型API估价，不是平台账单，也不包括CPU、服务器、存储、网络或人工成本。费率来源与有效期见[加固说明](HARDENING.md)及后端costs.py；本轮60条真实报告为99次尝试、90,675 Token，估价USD 0.04141068～0.08282175。实付由负责人核对平台账单。

## 优化策略

- 检索缓存键含工作空间/模型等上下文，默认TTL300秒；导入完成后使旧缓存失效。
- 默认最近8条消息，每条最多1200字符，RAG最多3篇、片段240字符，模型上下文有上限。
- triage与rewrite走低成本模型，resolution走主模型；默认DeepSeek Flash / V4 Pro，可配置。
- Docker默认启用每客户端每分钟240请求、全局32并发和2秒排队等待；超时返回503。原生开发默认是否限流以实际配置为准。
- 降级、失败和重试仍保留用量与原因，不能通过只统计成功调用美化成本。

## 并发压测与恢复核验

服务启动、账号初始化后，从backend目录执行：

```powershell
python -m scripts.benchmark_concurrency --base-url http://localhost:8000 --output-dir evaluation/reports/performance
```

自动登录只允许本机API；需要有效的私密初始测试账号。更改过初始密码后必须提供当前有效测试身份，不能继续假定旧初始密码可用。

脚本测试5/10/20并发，可配置每级请求数；失败返回非零，生成performance-latest.json/md。它查询可缓存知识，不写业务工单，但会更新运行观测数据。

本轮独立环境共90次请求、失败0；20并发客户端P95约110.436ms。**不是20并发完整LLM流程，也不是生产负载/SLA证明**。不把缓存接口吞吐量当作客服任务完成速度。

先等待所有任务/录屏结束，再在独立验收环境运行 `python -m scripts.verify_durable_metrics`；该脚本固定重启resolveai-acceptance的backend/worker，比较账本与登录会话，不用于任意业务实例。复现步骤见[交付指南](DELIVERY.md)。

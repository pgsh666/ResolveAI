# 安全、身份与工具边界

文档同步：2026-10-16。安全能力已实现基础版，不代表完整企业安全治理或无限场景保证。当前汇总见[验证结果](RESULTS.md)，公开副本范围见[发布说明](PUBLISHING.md)。

## 身份、会话与角色

- 密码使用Argon2，不保存明文密码。初始后台账号由本地私密.env.auth随机生成，不设公开默认密码；客户不能通过注册参数选择工作人员角色或占用保留的后台名。
- 客户自行注册按产品要求取消最低长度与字符组合限制，短密码、纯数字均可；仍拒绝空值、纯空格及超过128字符。此策略仅适用于客户注册，不把弱密码当作安全保证，启动初始管理员/修改密码仍保持12～128字符，后台不再提供创建账号；认证、限流、角色检查、哈希和会话机制不取消。
- 登录使用随机Token，数据库保存Token哈希及会话信息；浏览器Cookie为HttpOnly、SameSite=Lax，默认8小时过期。公网必须Secure，本机HTTP则不能启用Secure。
- 写请求验证X-CSRF-Token与来源。登录/注册有尝试限流，当前按来源地址计算；代理配置必须只信任明确的代理，不能接受任意伪造的转发头。
- 角色/对象授权在服务端执行，前端隐藏按钮不代替权限。客户只能操作自己的咨询；工作人员按工作空间访问，私有导入知识和任务有范围检查。
- 客户端仅 customer，后台仅 admin。管理员的 `/customer/*` 请求返回 403，前端页面及登录 next 同时限制；客户不能访问后台。同一浏览器普通标签共用会话，双端同时验收需独立浏览器配置或无痕会话。
- 管理员承担后台处理、审批及受控模拟工具执行，但账号权限仅限自己：可改显示名称/密码，不可创建、停用、改角色或操作客户/其他管理员。后端执行自有 ID 校验，账号列表仅返回自己；旧 agent/reviewer 登录及旧会话拒绝，历史审计保留且不自动提升权限。
- 审批/执行记录使用真实登录账号，前端传“管理员”或模型说“已授权”均不能提升权限。
- 修改自己的密码使该账号旧会话失效；角色与启用状态不能通过当前账号接口修改。
- 旧未绑定工单仅给默认项目工作人员，不按姓名猜测归属。基本工作空间检查不等于完善的企业租户管理、SSO、账号找回或数据生命周期治理。

未登录业务请求返回401，角色或CSRF不符返回403；跨所有权/工作空间的对象通常隐藏为404。health、登录/注册等必要入口例外。Jaeger是独立本机服务，不复用应用登录，不应暴露公网。

## 输入、证据与回复

用户消息、检索文档和客服改写指令是数据，不是授权指令；系统规则、可信业务政策、真实记录的工具结果分层处理。

- Pydantic约束类型/范围；手机号、身份证、银行卡、邮箱和常见明文凭证在指定业务入口脱敏。
- 注入、越权、敏感账号操作和风险由确定性规则拦截/复核；不能靠提示词授予权限。
- 缺订单不编造查询；需要政策依据却未命中时不调用方案模型编造结论，明确拒答/转人工。商品数据库可支持的普通详情无需同时命中售后知识，资料缺失先澄清，不自动越权或编造。
- 分析、改写、发送都检查事实依据：无工具记录不能说已退款/发券/补发/联系物流，无附件接收工具不能说已核验照片，政策到账时效不能冒充审批耗时，也不能编造入口。
- 本地工具降级不能冒充已核实的外部记录；模拟资金结果必须说明模拟，不表示真实到账。
- 分析失败有限重生成/转人工；改写失败保留原草稿；发送失败不向客户对话写入危险回复。
- 自动规则检查不是独立人工语义评审，也不能保证检测所有改写、无括号路径或复杂表达中的错误。

用户不确认解决时，发送回复不能自动关闭工单。Demo规则、真实SDK调用、模拟业务数据和真实外部业务应分别说明。

## 写工具防护

1. 只调用白名单及JSON Schema工具，查询与写权限分类。
2. 所有写执行要求有效人工审批，不因低于100元风险阈值而免确认。
3. HMAC凭证绑定工单、审批、工具、参数、幂等键和短有效期，MCP再次验签。
4. 再次核对订单、金额、动作、客户范围与权限；一般核查获批不是指定金额退款授权。
5. 数据库约束幂等键以及审批+工具，同一请求重复回放，不重复执行；同键不同参数冲突。
6. 保存真实操作人、尝试、结果、失败和审计。资金/发券目前仍为模拟，未接真实支付。

## 配置与发布

.env、.env.auth、Cookie、CSRF、审批凭证、数据库备份均不能进公开仓库/截图/录像；配置错误和API参数错误不回显密码/Key。备份包含业务与认证数据，私密保存不等于加密/异地灾备已完成。

客户评价包含用户输入，按当前工单权限读取并脱敏；后台显示历史评分与留言不意味着允许管理员修改客户账号。发布副本不携带评价、聊天、订单、手工 FAQ、用量台账、原始评测报告或运行数据库；只保留合成自动化输入和空白模板。若凭据曾进入 Git 历史，仅删文件或增加忽略规则无效，必须先撤销/轮换，再由仓库负责人处理历史。

默认绑定127.0.0.1；HTTPS模板和PUBLIC_DEPLOYMENT预检要求生产认证、Secure Cookie、精确HTTPS来源、强签名密钥与PostgreSQL强密码。只在隔离测试环境允许关闭认证，不能用于实际发布。

当前没有声称数据库账号已经最小权限拆分、完整租户生命周期、PII全面覆盖、操作系统无漏洞或生产安全认证。所有依赖审计通过只说明当时Python/JavaScript包没有已知告警。正式域名/DNS与部署授权、真实业务接口审批另行确认。

## 自动验证

从backend目录运行：

```powershell
python -m pytest tests/test_auth.py tests/test_security.py tests/test_tool_governance.py tests/test_hardening.py -q
python -m evaluation.run --fail-under 90
```

最后一条是免费离线规则评测，不是DeepSeek真实评测。当前双角色、侧栏、分类与资料权限浏览器验证为根目录 `node scripts/verify-commerce.cjs`；`verify-roles.cjs` 是同一验收的兼容入口。脚本自动启动隔离端口/SQLite/离线模型，不读取私密账号或调用付费模型。

历史客服版本真实60条回归曾观测高风险18/18、未审批写操作0，不能作为当前新增商城版本的成绩。当前离线规则评测与已知失败项见[指标汇总](RESULTS.md)；跨用户/角色/工作空间、CSRF、旧会话撤销、未审批写拒绝、幂等和危险回复拒发另有自动测试。这些是有限用例观测，不表示所有Prompt注入、所有表达和未来所有输入都被100%拦截。人工语义评分仍待完成。

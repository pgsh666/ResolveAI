# 公开副本、数据隔离与上传检查

更新日期：2026-10-16。

## 发布范围

公开仓库包含前后端源码、MCP、数据库迁移、合成自动化测试/评测输入、空白配置模板、启动脚本、通用知识和项目说明。测试输入只供显式测试命令在隔离库中执行，不是预置工单，不会在正常启动时写入业务列表。

不发布：

- 实际 `.env`、`.env.auth`、API Key、密码、Cookie、会话、CSRF 或审批令牌；
- 数据库、数据库备份、Docker 数据卷、用户试用的聊天/订单/工单/评价/手工 FAQ；
- 模型调用台账、逐条评测报告、Trace 导出、HAR、截图录像、日志、私密清单；
- 依赖目录、模型权重、构建/IDE 缓存、临时文件与原始运行产物。

模板中的空值或占位符不是可使用的真实凭据。账号初始化在每台机器自行生成私密管理员凭据；真实模型使用部署者自己的 Key，任何人都不应把 Key 发给仓库维护者。

## 清洁初始化

发布副本正常首次启动只初始化结构、通用知识和本机私密配置中的管理员，不自动创建示例工单、聊天、商品、订单、客户、评价或费用记录。商户自行上架，客户自行注册和下单。

此规则不是清库脚本：已有数据库和 Docker 数据卷仍包含原数据。不能通过删除源码中的数据库文件来证明已清理外部数据卷；也不要为发布而删除开发者原库。全新验收必须使用独立空库。

保留的 `backend/tests`、合成评测 JSONL 和浏览器脚本用于复现软件行为，测试记录只能在临时环境产生；测试输入不等于用户实际提交记录。不要运行会向正常服务写测试数据的联测脚本来准备公开展示环境。

## 上传前检查

1. 确认上传的是整理后的副本，不是正在使用的开发目录。
2. 检查 `git status --short`、`git diff --stat`，再检查已暂存文件，而不只依赖 `.gitignore`。
3. 已被 Git 跟踪的敏感文件不会因新增忽略规则自动消失；若曾泄露，先撤销/轮换凭据，再由仓库负责人处理历史。
4. 不提交任何 `.env` 或数据库，只保留 `.env.example` / `.env.local.example`。
5. 使用本机浏览器或 Git Credential Manager 登录 GitHub，不把访问令牌写入仓库地址、脚本、命令记录或文档。
6. 新生成的测试/浏览器/评测产物保持本地忽略，不加入上传目录。

本次整理不自动提交、推送、修改 GitHub 可见性或重写 Git 历史。素材授权、GitHub 登录/网络、最终公开范围仍由项目负责人确认。

## 重新部署提示

上传 GitHub 不等于部署网站。在同一机器启动副本前，确认端口、Compose 项目名和数据卷与原服务隔离。应用不处理真实资金，通用政策为项目样例，不可不经审核直接用于真实商家承诺。

前端卡通静态素材保留，仓库未替第三方素材授予许可。公网部署还需域名、HTTPS、私密强凭据、额外安全核验和真实业务授权，详见[交付](DELIVERY.md)与[安全边界](SECURITY.md)。

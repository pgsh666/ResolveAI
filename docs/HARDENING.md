# ResolveAI 加固与复验说明

文档同步：2026-10-13。当前完整启动命令、跨平台准备及复验步骤统一见[交付指南](DELIVERY.md)，指标口径见[性能与成本](PERFORMANCE.md)。以下记录工程加固与已有验证，不代表本次文档更新重新运行付费评测。

工程加固已补齐回复事实校验、登录/所有权/角色隔离、可恢复数据库迁移与备份、跨重启用量台账、机器处理和客户解决周期、依赖锁定/漏洞审计，以及 HTTPS 上线配置模板。独立人工质量复核与正式公网部署仍需后续完成。

## 启动与前端验收

项目根目录运行 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`。脚本只启动一套前端；若打开两个页面，分别是客服与客户入口。首次生成私密 `.env.auth`，已有文件与账号密码不会被覆盖。在本地打开该文件查看 admin / agent / reviewer 的随机初始密码，切勿上传或发到聊天中。可在前端“修改密码”；更改后旧会话失效，初始文件不再代表已改过的密码。

1. 在登录页点“客户注册”，提交问题。客户不能进入后台，另一客户不能读取或确认此工单。
2. 使用另一个浏览器或独立浏览器配置登录 agent，在工单中心运行 Agent。可以处理、改写、发送，但不能批准退款。
3. 登录 reviewer，批准风险动作；审批记录使用真实登录账号，不能由输入框假冒。只有审批人/管理员可以执行已批准的模拟退款；重复操作由幂等机制阻止。
4. 客服发送后，客户端仍显示“处理中”；可以继续对话，仅客户主动确认后显示“已解决”。
5. 管理员在“账号管理”创建/停用/调整角色，在“效果分析”查看持久化用量和耗时。知识导入及评测操作仅管理员可执行。
6. 尝试发送“我们已联系承运商，正在补发商品”这类没有工具依据的回复，应该被拒绝，且对话记录不能多出这条消息。

头像、客户消息右侧、多轮对话及同窗口导航保留。原有未绑定身份的历史工单只供默认项目的工作人员查看，不按名字猜测归属给新注册客户。

Linux/macOS 克隆者可先运行 `python3 scripts/bootstrap-auth.py`，无需第三方依赖，会以 0600 权限生成同样的私密文件，然后按 Docker 文档准备语义模型并启动。Windows 使用上述 ACL 版 PowerShell 脚本。

## 自动检查与证据

- `scripts/verify.ps1`：本地测试、离线规则回归、前端检查与构建；任何一项失败都会停止，不再误报成功。
- `backend/scripts/verify_closeout.py`：真实 PostgreSQL/pgvector、MCP、Redis/SSE、DeepSeek、Checkpoint 重启、审批、幂等、模拟退款、多轮/客户确认、七节点追踪。
- `scripts/verify-roles.cjs`：四种独立浏览器角色、工单所有权、危险回复拦截、账号页和用量页。
- `scripts/record-demo.cjs`：真实浏览器录屏；输出保存在 `output/hardening/browser/`，不覆盖先前收尾证据。
- 录屏先检查方案的金额与退款动作：一般人工核查获批不代表指定金额退款获批。自动化验收曾发现并修正退款审批步骤的等待条件，没有绕过资金规则；最终明确退款场景已重录通过。原始录屏和逐次运行结果保留在本地。
- `backend/scripts/verify_durable_metrics.py`：仅重启隔离验收服务，比较模型与耗时台账完全一致，同时确认登录会话保持有效。
- `backend/scripts/benchmark_concurrency.py`、`verify_async_tasks.py`、`verify_tracing.py` 已适配登录。自动登录只允许本项目本机地址，不能把私密凭据发往任意 URL。

## 数据库升级与备份

Alembic `0001` 接管既有九张业务表，`0002` 增加身份/所有权/任务范围/知识空间/用量与耗时表及 Checkpoint 字段。迁移不删除业务表，重复启动不重复迁移；发现缺失必要列时拒绝盲目接管。默认拒绝破坏性降级。

一键启动会先对已有 Docker 数据库执行二进制 `pg_dump -Fc`，存入仅本机用户可访问的 `.backups/`，备份失败则停止启动。首次全新数据库无需备份。备份没有自动上传，也不允许自动覆盖原数据库恢复。

手动备份可运行 `scripts/backup-database.ps1`。备份恢复演练可运行 `python scripts/database-safety.py --container <明确的项目数据库容器名> --restore-check`：只创建 UUID 命名的独立数据库，恢复后比较每张表的行数和内容摘要；不删除或覆盖原库。备份与恢复副本都保留，勿直接执行 `docker compose down -v`。

本轮在独立 `resolveai-acceptance` 项目中，迁移前/后备份恢复均成功；原九张表内容完全保留，包括 512 维语义向量、工单、审批、审计和 Checkpoint。没有迁移或改动正在使用的本地业务库；普通启动时才执行对应库的升级。

## 成本与耗时的口径

每一次模型尝试都保存在 `model_usage`，包括返回了 Token 后的解析失败、重试、质检重生成与改写。每段工作流保存在 `workflow_runs`，包括排队、处理、失败和审批恢复。重启不会依靠内存重新计数。旧版本仅有最终摘要的记录不能证明完整重试用量，费用标为未知，不回填伪造账单。

DeepSeek 估价使用 [官方价格](https://api-docs.deepseek.com/quick_start/pricing/) 的 2026-10-12 快照，分缓存命中/未命中，给出峰谷上下界；不是实付账单。到 2026-11-11 后如未更新费率或提供显式费率，则标为未知。Demo 没有 API 费用，模拟 Token 与真实调用分开记录。

机器端到端从入队/同步启动至工作流结束，包含排队和失败，不包含人工等待；客户确认解决周期另从工单创建至客户主动确认，包含人工/客户等待，仅统计明确解决的样本。不能把 API 尝试 P95 或缓存检索 P95 冒充完整客服解决时长。

## 依赖与正式发布

`backend/requirements.lock` 冻结已验证的 Python 3.11 Linux 部署依赖（含 pip/setuptools），前端保留 package-lock。CI 使用锁文件并执行测试、前后端审计；已做本地同等验证，但未声称远端 GitHub Actions 已实际运行。Windows 原开发环境有一条 Starlette/AnyIO 弃用提醒，不是漏洞；最终 Linux 镜像测试没有该提醒。

本机默认只绑定 127.0.0.1，不会意外向局域网公开数据库、Redis、MCP 或追踪服务。`docker-compose.public.yml` 和 `deploy/Caddyfile` 预备同域 API、Secure Cookie、HTTPS、固定可信代理地址；模板已校验，但未启动公网服务。Caddy 的证书管理依赖可控域名、DNS 与开放的 80/443，[官方条件](https://caddyserver.com/docs/automatic-https) 必须先满足。

正式发布前由您确认服务器/域名/DNS/访问策略，私密配置中的 PUBLIC_DOMAIN 与现有强数据库密码必须正确；不能只修改环境变量来假装已更改旧数据库密码。核对网络 172.29.241.0/24 不冲突。先备份，再验证 Compose 模板，运行容器内 `python -m scripts.preflight --public`；生产认证、Secure Cookie、精确 HTTPS 来源、强签名密钥、PostgreSQL 强密码任一缺失都会拒绝。不要把本机 HTTP 的 AUTH_COOKIE_SECURE 设为 true，否则 Cookie 不会正常发送。
